# Docker Image Instructions

The Dockerfile and scripts in this folder create a working image of the [PaxML](https://github.com/google/paxml) stack.
There are a few basic steps to create working image:

## Download all the relevant code
Numerous libraries with dependencies on specific commits are required. The can be downloaded by running:

```bash
$ ./clone-all.sh
```

Some of the repos are private and expect an SSH key to have been configured.


## (Optional) Start a remote Bazel cache

The XLA builds compile 1000s of files and can take a very long time. If you may need to rebuild an image
with updates to any of the repos, it is highly recommended to set up a remote bazel cache.
It should be sufficient to run:

```bash
$ ./start-cache.sh
```

This downloads and starts a Docker container with the remote cache running on gRPC port 9092.
The script sets up the cache directory to be `$(pwd)/cache` and sets an upper limit of 100GB. 
These parameters can be changed in the script.  The XLA builds generate as much as 20GB of 
files for a clean build.  

The Dockerfile is already configured to point the XLA builds to the expected gRPC port.
If no cache is running, XLA will print a warning but continue building without error.
However, the docker build must still have the host network mapped into the docker build
or the build will crash with a network error.

## Generate a development docker image

There is a `./build-cached.sh` script that starts a docker build with the correct 
arguments for mapping the host network into the container. Even though the
Bazel cache is optional, the build still requires the host network mapping.

```
$ ./build-cached.sh
```

This will produce an image named `legate-jax` that can be tagged and pushed where needed.
The image will contain all the code from the repos and installs Python libraries in 
editable mode and enables rebuilds of the C++ libraries.

## Generate a production image

A stripped down image that only install artifacts and does not contain any of the code or build files
can be generated by running:

```
$ ./build-multi-stage.sh
```

The same guidelines about the Bazel cache apply to the multi-stage Dockerfile.

## Tags for reproducibility

The Dockerfile copies a `tags` file into the image for reproducibility.
This is generated from the `tags.sh` script. The standard build scripts
will run this script to generate them automatically.
